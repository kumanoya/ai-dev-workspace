現在の会話から「チームに共有する価値のある学び」を抽出し、`docs/notes/YYYY-MM-DD-<slug>.md` に書き出す。運用ルールとテンプレートの権威は [docs/notes/README.md](../../docs/notes/README.md)。

## 手順

1. 会話を振り返り、メモにする学びを特定する。対象は「調べないと分からなかったこと・意外だった仕様・ハマりと解決」であり、作業ログや自明な操作手順は対象外。トピックが複数あれば1トピック1ファイルに分ける。
2. 書き出し先を決める: `docs/notes/YYYY-MM-DD-<slug>.md`。slug は `$ARGUMENTS` から、なければ学びの内容から英語 kebab-case で生成。日付は今日。
3. README のテンプレートに沿って書く。**読者は文脈を知らないチームメイト**なので、会話内でしか通じない略語・言い回し・「さっきの」等の指示語は使わない。
4. 書き上げたら秘匿情報チェックを行う: 案件固有の用語・顧客名・URL/ID/キーの実値が含まれていないか確認し、あれば一般化して書き直す（公開リポジトリのため）。
5. メモのパスをユーザーに伝え、TL;DR を会話に再掲する。

## 制約

- コミットはしない（ユーザーが `/commit` する）。
- 既存メモと同じトピックなら新規作成せず、その既存ファイルに追記・更新する。
- 会話ログの転記はしない。学びとして再構成した文章だけを書く。
