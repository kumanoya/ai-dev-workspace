# create-pr — Pull Request の作成

現在のブランチの変更を1件の Pull Request にまとめる。PR の作成だけに専念し、merge・ブランチ操作・コードの修正はしない。

## 入力（チャットメッセージから拾う）

- **目的の補足**（任意）: PR の目的・背景。無ければ会話の文脈とコミットログから組み立てる
- **Issue**（任意）: `#数字` またはチケット URL が含まれていればそれを使う。**無ければ「なし」とする。差分やコミットログから推測して補完してはならない**（無関係な Issue を自動クローズしてしまうため）
- **--draft**: 含まれていれば draft PR として作成

## 手順（コスト配慮: ツール呼び出しは最小限に）

1. `git branch --show-current` を確認する。`main` なら**何もせず中断**。
2. `gh pr view --json url,state` で既存 PR を確認する。既に open な PR があれば作成せず、その URL を報告して終了。
3. `git log main..HEAD --oneline` と `git diff main...HEAD --stat` を**各1回**で差分の全体像を掴む。本文作成に必要なファイルだけ個別に diff を見る（全文 diff の一括取得はしない）。
4. 未コミットの変更が残っていれば PR を作らず中断し、先に `/commit` するよう促す。
5. `.github/pull_request_template.md` を読む。**これが PR 本文フォーマットの権威**（存在すればそのセクション構成を使う）。
6. `gh pr create` で作成する:
   - タイトル・本文とも**日本語**。タイトルはコミット規約と同じ `<type>: <要約>` 形式（type の一覧・書式は `/commit` のプロンプトファイルが権威）。破壊的変更は `<type>!:` とする
   - 本文はテンプレのセクション構成をそのまま使い、各セクションを埋める。`--body` に heredoc で渡す（`--body` を渡すとテンプレは自動適用されないため、自分で埋めた全文を渡す必要がある）
   - テンプレが読めない場合のみ、`## 概要` / `## 主な変更点` / `## 確認方法` の3セクションにフォールバックする
   - 記入ガイドの HTML コメント（`<!-- ... -->`）は**削除して**提出する
   - 「関連 Issue / チケット」: Issue があれば `Closes #12` または URL、無ければ `なし`
   - **チェックボックスは、自分が実際に実行して確認できた項目だけチェックする。未実行・未確認の項目は空のまま残す**（人間のレビュー判断を狂わせるため、埋めることを目的にチェックしない）
   - 各セクションは簡潔に。箇条書きは原則5項目以内
   - 末尾に `🤖 Generated with GitHub Copilot`
   - リモートにブランチが無い場合、`gh pr create` が push を提案・実行することがある。これは許容する（このプロンプトの起動自体が人間の確認を意味する）
7. 作成した PR の URL とタイトルを報告する。中断した場合は理由（main ブランチ・未コミット変更あり・既存 PR あり・認証エラー等）と次のアクションを報告する。

## 制約

- **`gh pr merge`・`gh pr close`・ブランチ削除・`git push` の直接実行・force 系操作は禁止**。
- ファイルの作成・編集・削除は一切しない。
- 認証エラーが出たらリトライせず、人間に報告して認証の確認を促す。
