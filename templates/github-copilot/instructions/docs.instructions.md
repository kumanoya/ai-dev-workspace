# ドキュメント執筆の方針

**ドキュメントに書く情報**: React/TypeScript/Git に慣れたエンジニアでも「コードや公式ドキュメントを見ても分からない」情報のみ。フレームワークの基本操作・一般的なコマンドは書かない。

書くべき情報の種類:

- **プロジェクト固有の設定・制約**（例: 各プロトタイプのポート番号は `vite.config.ts` が権威、ドキュメントの例示値より優先）
- **チームで揃えるべきルール**（例: コミット日本語必須）
- **経験則・ハマった事例**（例: 近似色はスクリーンショットで目視区別不能 → 定義値で確認する）

書かない情報（レビューで削られる典型）:

- **過去の状態・誤りの注記**（「以前は◯◯だった」「正しくは◯◯、△△ではない」等）
- **実ファイルの内容の丸写し**。設定値・コードは権威ファイルへのリンク＋方針の説明に留める（二重メンテ防止）
- **インシデント・失敗談を起点にした枠組み**。教訓は中立なルールとして書き直す

経験則・学びの時系列メモは `docs/notes/` へ（チャットで `/save-note` を実行）。同ディレクトリは本方針の適用外で、`docs/notes/README.md` が存在すればそれが運用の権威。
