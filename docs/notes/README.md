# docs/notes — 学びメモ（TIL）

日々の開発で得た小さな学び・調査結果を時系列で残すログ。用途はチームでの雑談・情報共有・ブログ記事のネタ。

**本ディレクトリは CLAUDE.md「ドキュメント・コメントの方針」の適用外。** あちらは恒久ドキュメントの規範で、経緯・失敗談・過去の状態の記載を禁じているが、ここはむしろ「何にハマって、どう調べて、何が分かったか」の経緯こそが価値。遠慮なく書く。

## ルール

- **1トピック1ファイル**、ファイル名は `YYYY-MM-DD-<slug>.md`（slug は英語 kebab-case）
- **公開リポジトリなので、案件固有の用語・顧客名・秘匿情報（URL・ID・キーの実値）は書かない**。一般化して書く
- メモは消さない（ログなので）。恒久ルールに昇格すべき知見が出たら docs/ 本体や CLAUDE.md へ中立なルールとして書き直し、メモ側はそのまま残す
- 書き出しは `/save-note` コマンドで定型化してある（手動で書いてもよい。その場合も下のテンプレートに沿える）

## テンプレート

```markdown
# タイトル（学びが一文で分かるように）

- 日付: YYYY-MM-DD
- タグ: `claude-code` `figma` など
- 用途: 雑談ネタ / ブログ候補 / 共有済み

## TL;DR

3行以内で結論。

## 何があったか

きっかけ・文脈。どんな作業中に、何を疑問に思ったか。

## 詳細

調べたこと・分かったこと。読者は文脈を知らないチームメイト。

## ブログにするなら（任意）

記事の切り口・想定読者のメモ。
```
