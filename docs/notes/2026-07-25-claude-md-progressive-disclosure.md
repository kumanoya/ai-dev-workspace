# CLAUDE.md からリンクした docs は自動では読み込まれない — 展開されるのは @import だけ

- 日付: 2026-07-25
- タグ: `claude-code` `context-engineering` `cost`
- 用途: 雑談ネタ / ブログ候補

## TL;DR

- CLAUDE.md の Markdown リンク（`[docs/foo.md](docs/foo.md)`）はただのテキストで、リンク先は自動読み込みされない。自動展開されるのは `@path/to/file` という import 構文だけ
- したがって「CLAUDE.md は要点＋権威ファイルへのポインタ、詳細はリンク先」という構成は、コンテキストの無駄遣いにならない。むしろ推奨形（progressive disclosure）
- モデルごとに CLAUDE.md を出し分ける機構はない。実務上のレバーは「詳細手順をスキル/サブエージェント定義に置く」こと

## 何があったか

CLAUDE.md が `docs/ai-cost-optimization.md`（約19.5k文字）などをリンク参照しているのを見て、「セッション開始のたびに docs 全文がコンテキストに載っているのでは？　人間向けの長文がプロンプトを圧迫していないか？」と不安になった。

## 詳細

### 読み込みの仕組み

セッション開始時に自動でコンテキストへ載るのは CLAUDE.md 本体のみ。リンク先が読まれるのは、エージェントが作業中に「この権威ファイルの確認が要る」と判断して Read したときだけ。必要なときに必要な分だけ読む、いわゆる progressive disclosure（段階的開示）がリンク方式の意図。

例外は `@docs/foo.md` のような import 構文で、これは CLAUDE.md 読み込み時にその場で展開される。つまり「常に読ませたいなら @import、必要時だけならリンク」という使い分けになる。うっかり長文ドキュメントを @import すると毎セッション全文が載る。

### CLAUDE.md 最小化がベストプラクティスである理由

CLAUDE.md は全セッション・全ターンのプロンプト先頭に載り続ける。肥大化の害は2つ:

1. トークンコストの恒常的な増加（プロンプトキャッシュは効くがゼロにはならない）
2. 指示の希釈 — 本当に守らせたいガードレールが大量の情報に埋もれて遵守率が下がる

基準は「毎回必ず効いてほしいルールとポインタだけを残し、詳細は権威ファイルへ」。

### モデルによる情報量の調整

CLAUDE.md をモデル別に切り替える機能は存在しない。ただし構成で実質同じことができる:

- 強いモデルが回すメインセッションには、ポインタだけ渡して必要時に自力で権威ファイルを辿らせる
- 手順への忠実さが欲しい定型作業は、小さいモデルのサブエージェント＋詳細手順入りのスキル定義にする（スキルはそのエージェント起動時にだけ読み込まれる）

「詳細をどこに書くか」がそのまま「どのモデルに何を読ませるか」の制御になる。
